# OmniDesk 常驻监控

统一云端的 Go 监控模块和跨平台采集端。通过本仓库根目录 部署账号、同步及监控，PC 在“账号”配置一个云端地址并登录；所有节点按当前账号隔离。关闭客户端不停止采集端。

## 功能与范围

- CPU、各核心、负载、steal、iowait、内存、Swap、磁盘、inode、磁盘 I/O 和网卡指标。
- SQLite 持久化，默认 60 秒采集上报，可在 5–86400 秒内设置。历史查询提供小时、日、周、月视图；原始指标保留 24 小时，随后合并成分钟记录保留 32 天，按查询范围分桶展示，数据量随节点数增长。
- Agent 本地持久化流量、序列和待上传队列；断网后按序补传，上报幂等。
- 每台节点独立令牌，管理令牌与上报令牌隔离；服务端仅存令牌哈希。
- 手动到期/价格资料、周期流量限额、初始用量、每月重置日与时区。
- 资源、失联、到期、额度提醒；事件存库，可选通用 JSON Webhook。

使用 OmniDesk 统一账号接口，不兼容 Komari Agent 或管理接口。Agent 支持 Linux x64/ARM64 与 Windows x64；Windows 安装脚本与服务方式见 `../deploy/UNIFIED-CLOUD.md`。

## 构建

需要 Go 1.26 或更高版本。

```sh
go test ./...
CGO_ENABLED=0 go build -trimpath -o bin/omnidesk-monitor-server ./cmd/server
CGO_ENABLED=0 go build -trimpath -o bin/omnidesk-monitor-agent ./cmd/agent
```

交叉编译 Linux 时设置 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`，ARM64 将架构改为 `arm64`。

## 服务端部署

部署本仓库根目录，统一 Node 入口对外提供 `/v1/monitor/...`，Go 模块仅在容器回环接口提供存储和采集处理。内部管理令牌只供 Node 到 Go 认证，不交给客户端或采集端。PC 在“账号 → 云端监控”启用，无需第二个地址或令牌。

Agent 的 `serverUrl` 必须为 `https://你的云端域名/v1/monitor`，上报路径为 `/v1/monitor/reports`。不提供旧独立监控路径。详见 `../deploy/UNIFIED-CLOUD.md`。

## VPS 接入

OmniDesk 0.6.21 起，登录账号并启用监控后连接 Linux SSH，在终端侧面点击「加入监控」，即可自动创建节点、安装采集端并接收上报，无需手动新建。也可从总览「添加监控服务器」选择已有 SSH 连接。已有节点在列表及详情顶部提供安装/重新安装入口，名称、分组沿用连接，其余资产资料可后续编辑。支持 Linux x64/ARM64、systemd、root 或免密码 sudo。程序随客户端内置，通过 SFTP 上传并设为开机自启；安装后通过 HTTP(S) API 上报，不依赖桌面持续在线或 SSH 连接。

自动安装独立使用 `/etc/omnidesk-monitor-agent/agent.json` 和专用用户 `omnidesk-monitor-agent`，状态仍为 `/var/lib/omnidesk-monitor-agent/state.json`。令牌加密保存在客户端保险箱。旧节点未保存令牌时需明确同意更换令牌。安装器拒绝覆盖下面的旧版手动配置和非受管服务；旧部署请继续按原方式维护或先备份迁移。自动重装保留状态，失败备份位于 `/var/backups/omnidesk-monitor-agent`。

以下为原手动部署流程：

1. 客户端「服务器监控 → 添加常驻节点」，填写名称和资料，保存后下载配置。节点令牌仅在创建/更换时返回。
2. 将对应 Linux 架构的 Agent 放到 `/usr/local/bin/omnidesk-monitor-agent`，赋予执行权限。
3. 创建专用系统用户及组 `omnidesk-monitor`，不授予登录权限。
4. 将下载的配置放到 `/etc/omnidesk-monitor/agent.json`；建议目录 root:omnidesk-monitor、0750，配置 root:omnidesk-monitor、0640。配置含令牌，不应允许其他用户读取。
5. 将 `deploy/omnidesk-monitor-agent.service` 安装至 systemd 的服务目录，执行 `systemctl daemon-reload`，再启用并启动 `omnidesk-monitor-agent`。
6. 通过 `journalctl -u omnidesk-monitor-agent` 查看启动问题。服务为专用用户创建可写状态目录，默认不需要 root 采集权限；受限系统仍需验证可读取的指标。

`includeNics` 选择对外网卡，例如 `["eth0"]`。留空自动排除常见回环、容器和隧道接口；使用隧道作为实际出口时应明确指定。不要同时统计重复经过的桥接和虚拟接口。

每台 VPS 使用自己的令牌及状态文件。不要复制其他节点的状态文件。更换令牌后更新 VPS 配置并重启 Agent；停止与卸载通过系统服务管理，和桌面显示开关相互独立。

## 服务商与地区自动识别

SSH 监控使用连接地址对应的公网 IP 查询归属；添加后异步识别，监控采样时按需刷新。内网 IP 不发送到查询服务。常驻节点由新版 Agent 查询自身公网出口 IP，并把结果放入指标的 `discovered` 字段，现有服务端可直接保留和返回。

查询通过 HTTPS 访问 ipwho.is，不携带 SSH 凭据、管理员或节点令牌。自动信息包括网络归属、国家/地区/城市、公网 IP、ASN 和识别时区。成功缓存 24 小时，失败重试间隔至少一小时；查询有超时和响应大小限制，异步执行，不影响指标和流量队列。Agent 的识别结果和尝试时间与本地状态一起保存，可在配置中设置 `"disableDiscovery": true` 停止外部识别查询。

手动服务商和地区优先显示；字段留空时回退到自动结果。网络归属可能是机房或上游运营商，不能保证识别实际销售商；公网出口也可能与服务器位置不同，IPv4 和 IPv6 的归属可能不同。识别时区仅供展示，不更改账单统计时区。到期、价格、额度和续费资料仍按手动设置。

## 流量与历史边界

- 流量按网卡原始字节计数差值累计，和实时速率图分开计算。
- 首次采样建立基线，安装前的用量无法自动恢复。可为指定计费周期填写商家后台已有上传/下载量。
- 队列同时受约 24 小时数据年龄与最多 8640 个报告限制。溢出后依靠累计计数补回总字节，但缺失时段内的准确时间分配无法恢复，会标记非完整周期。
- 状态文件每次采样原子写入并同步。断电、采集停止、网卡重建或系统重启仍可能漏掉未采样流量，不承诺账单级准确性。损坏状态文件保留并报错，不静默清零。
- 服务端重启保留已提交记录，重复上报不重复计流量。Agent 失联时保留最后采样时间。
- 到期日和流量重置日独立。重置日为 29/30/31 时，短月取月末，随后月份恢复原设定日期。
- 计费支持上传、下载、相加、取最大或最小。额度输入 GB 为十进制，指标显示按 1024 换算；结算以服务商账单口径为准。
- 历史按查询范围分桶展示；原始采样保留 24 小时，分钟记录保留 32 天。大量节点部署前需评估数据库存储和查询负载。

## 提醒与备份

服务端每 30 秒检查：按节点采集上报周期动态判断失联；CPU/内存达到 90% 持续 5 分钟；磁盘达到 90%；到期前 7/3/1 天及到期后；流量达到 80/90/100%。状态与事件持久化，同一次告警去重。

可设置 `OMNIDESK_WEBHOOK_URL`。未配置时只保存提醒记录；配置后由服务端发送，与桌面是否运行无关。接收方按实例与事件 id 去重，避免重试造成重复通知；不要提交包含密钥的 Webhook 地址。

用 SQLite 在线备份工具，或停止服务后一起备份数据库及 WAL。不要仅复制正在写入的主数据库文件。Agent 状态文件也应备份。

接口见 `docs/PROTOCOL.md`。

## 节点删除

管理员接口 `DELETE /v1/nodes/{id}` 幂等删除节点及关联历史、流量汇总、提醒，并立即使节点令牌失效。删除使用数据库事务，并拒绝在删除后写入迟到上报或迟到提醒。客户端删除不会修改保存的 SSH 连接或自动卸载 VPS 程序；重新接入已删除的受管节点时，安装器先备份旧采集状态，新节点从本次接入重新统计。旧版服务端需更新程序后才支持删除，无数据库迁移。

终端已关联后台节点后，状态面板直接读取服务端指标，不再通过 SSH 重复采样。连接探测仅确认 Linux 和受管配置，不上传或运行会话采集脚本。
